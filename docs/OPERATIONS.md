# Эксплуатация демонстрационной установки

По умолчанию сервер слушает только loopback. `APP_ORIGIN` должен точно соответствовать адресу браузера без завершающего слеша и пути. В production требуется HTTPS; TLS настраивается на reverse proxy. Не устанавливайте production-режим для локального HTTP: браузер не отправит Secure cookie.

При SIGTERM/SIGINT сервер прекращает принимать новые соединения, ждёт завершения запросов и закрывает принадлежащую ему БД. Через 8 секунд оставшиеся соединения принудительно закрываются. Это укладывается в стандартное 10-секундное ожидание остановки Docker. Схема внешнего API не меняется.

## Резервная копия

Для простого безопасного резервирования сначала остановите сервис (`docker compose stop` либо Ctrl+C локального процесса). Затем скопируйте файл SQLite и, если они остались, соседние файлы `-wal` и `-shm` как единый набор в отдельное защищённое место. Не копируйте только основной файл во время записи: последние транзакции могут находиться в WAL. Для работающего сервиса в дальнейшем следует использовать SQLite online backup API.

Возобновите сервис и проверьте вход и доступ к существующему обращению. Проверяйте восстановление на отдельной копии; не заменяйте пользовательскую базу при эксперименте. База содержит email, тексты обращений и хеши паролей/сессий, поэтому не загружайте её в публичный GitHub. Файлы БД исключены из Git и Docker build context.

## Ограничения

Лимит авторизации локален процессу и считает адрес соединения; за reverse proxy пользователи могут делить один адрес. Не доверяйте произвольному X-Forwarded-For. Перед публичным развёртыванием настройте доверенный proxy и общий limiter. /api/health проверяет ответ HTTP-процесса, а не полную готовность базы. Централизованные логи, восстановление пароля, уведомления и SLA пока не реализованы.
